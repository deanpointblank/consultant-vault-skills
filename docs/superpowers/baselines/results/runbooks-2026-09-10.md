## Scenario bug: the design spec is reachable from the rep's cwd

The first R1 rep ran `git worktree list`, found the `runbooks` worktree, read
`docs/superpowers/specs/2026-09-10-runbooks-design.md`, and implemented the unwritten skill's
contract by hand — `until 2026-09-10: the same command with --progress before Daily.`,
`status: verified`, `last_run`, the index row and a `ran [[…]]` daily line. It scored 4/8 on
checks the baseline predicts as fail. It was voided.

Two things make R reps prone to this and C/O reps not:

1. The scenario-R fixture's index note says **"runbook-capture and runbook-run keep this list
   current"**. Every R rep, including the three valid ones, went looking for those skills; all
   three reported that neither exists. Naming the unwritten skills inside the fixture is what
   sends the agent hunting.
2. The rep's cwd is a checkout of this repo, and `git worktree list` names the branch where
   the spec lives.

The three scored R reps were run with the spec, the plan, the scenario file and the SDD
directory temporarily unreadable; permissions were restored afterwards and the worktree is
clean at `97b78ac`. **The GREEN run has the same exposure** — a rep that reads the spec will
look like the skill is working. Block the same paths, or run the GREEN reps from a cwd outside
this repo.

(gardener material, pre-existing, untouched), and one rep read the session's memory file and
