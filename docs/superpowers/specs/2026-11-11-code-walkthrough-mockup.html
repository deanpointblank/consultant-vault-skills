Three ways to read a walkthrough

Same 14 stops each time. Stops 1–3 are real; the rest are stubs. Try each, then pick one or say what to mix.

Width: 

One stop fills the view. Click a dot to jump, or use Prev / Next, or the ← → keys.

This box is 800px wide, like the Obsidian note pane.

← → keys work

Good for

  • A first read, start to end. One stop fills the view, so nothing else competes.
  • Code and its explanation side by side. The dots show how far along you are.

Costs

  • You never see the whole journey at once. Comparing two stops means clicking back and forth.
  • To look one fact up, you have to know which stop holds it.

All 14 stops on one screen. Click a row to open it in place; opening one closes the others.

This box is 800px wide, like the Obsidian note pane.

Good for

  • Scanning the whole journey in one screen, then looking one thing up fast, say in a meeting.
  • Finding the gaps: one click shows only the stops with a reason that is not recorded.

Costs

  • Reading in order means opening each row in turn. An open stop pushes the rest down.
  • No picture of the flow, only names.

The map stays in view while you read. Prev / Next (or ← →) move the map and the stop together. Click a spot on the map to jump.

This box is 800px wide, like the Obsidian note pane.

In the real page the map animates. Here a box marks the spot.

Good for

  • Always seeing where you are in the whole flow while you read the code.
  • The map doubles as the table of contents: click a spot to jump.

Costs

  • The map takes about half the height, so less code fits. At note-pane width the map text gets small.
  • What, Data and Why are tabs, so you see one at a time.
